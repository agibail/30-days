# AGENTS.md — 30 Days

Instructions for any AI agent (Claude Code, Codex, Cursor, etc.) working in this repo.

## The project

The owner makes **one new project a day for 30 days**. Each day can be a website, images, video, or a mix. Everything is published as a gallery on GitHub Pages, and every iteration should stay viewable.

## The directive: commit and push after every turn

**At the end of every turn that changes files, run:**

```bash
./30 save <day> "short description of what changed"
```

(Leave out `<day>` for repo-wide changes: `./30 save "Tweak gallery styles"`.)

That one command does everything required:
1. **Snapshots** the day's `site/` as a new iteration (`days/day-NN/vNN/`) if it changed.
2. **Logs** the change in `CHANGELOG.md` (newest first). This is the running markdown record of changes. Never skip it and never rewrite past entries.
3. **Rebuilds** `data/manifest.js`, which drives the gallery.
4. **Commits** (`Day NN: message`) and **pushes** to GitHub, which redeploys Pages.

If the push fails (no network or auth), say so to the user. The commit is still saved locally; retry with `./30 push`.

Write messages from the user's point of view: *"Add parallax hero and dark mode"*, not *"edit index.html"*.

## Layout

```
30                    helper CLI (bash). ./30 help
index.html, assets/   the gallery site (static, no build step)
data/manifest.js      GENERATED by ./30 build. Don't hand-edit.
config/site.env       start date, media backend, size limits
config/r2.env         Cloudflare R2 secrets (gitignored; never commit)
templates/site/       starter page for website days
days/day-NN/
  README.md           front matter (title, date, type) + notes shown on the day page
  site/               the current website for that day (optional)
  v01/, v02/ …        frozen site iterations (created by save/snapshot; don't edit)
  media/              images & videos stored in the repo
  media.txt           URLs of media hosted on R2 (one per line)
```

## Common tasks

| Want | Command |
|---|---|
| Start a day | `./30 new <day> "Title" website\|image\|video\|mixed\|other` |
| Add a website to an existing day | `./30 site <day>` |
| Add images / a folder of images / video | `./30 add <day> path/to/file-or-folder …` |
| Send big files to Cloudflare R2 | `./30 add <day> --r2 path/to/video.mov` |
| See progress | `./30 status` |
| Preview locally | `./30 open` |

`<day>` can be a number or `today`.

## Rules

- Work inside `days/day-NN/`. Edit only the current `site/`. **Never modify `vNN/` folders**, because they are the history.
- Day websites should be self-contained static files (HTML/CSS/JS). A CDN is fine. Reference that day's media with `../media/file.jpg` so snapshots keep working.
- Keep media files under ~90MB each in git. Larger ones go to R2 (`--r2`). If R2 isn't configured yet, tell the user rather than committing huge files.
- Never commit `config/r2.env` or any secret.
- Update the day's `README.md` notes when it helps: what it is, the tools used, what was learned.
- Runs on stock macOS. The CLI uses only bash 3.2, curl, sips, and git. Don't add Node/Python dependencies to the tooling without asking.
